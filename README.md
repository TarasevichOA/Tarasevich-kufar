# Kufar-TarasevichOA: Test Automation Framework

Репозиторий содержит современный фреймворк для автоматизации тестирования площадки объявлений Kufar. Проект сочетает в себе автоматизацию пользовательского интерфейса (**UI**) и проверку серверной части (**API**). Реализован параллельный запуск тестов для обеспечения высокой скорости сборки.

---

## Технологический стек и зависимости

Фреймворк построен на актуальном и производительном стеке автоматизации:

* **Язык программирования:** Java 19
* **Тестовый движок:** JUnit 5 
* **UI Автоматизация:** Selenium WebDriver (v4.x)
* **API Автоматизация:** Rest Assured (v6.x)
* **Генерация данных:** Datafaker (для создания реалистичных тестовых сущностей)
* **Матчеры/Проверки:** AssertJ (для гибких и читаемых ассертов)
* **Логирование:** Log4j2 
* **Отчетность:** Allure Report 
* **Сборщик проекта:** Apache Maven

---

## Ключевые особенности фреймворка

* **Параллельное выполнение:** В `pom.xml` настроен встроенный параллельный запуск тестов средствами JUnit 5 (`fixed` стратегия конфигурации на **6 параллельных потоков**).
* **Многослойные тесты:** Поддержка как классического UI-тестирования (Selenium), так и быстрых интеграционных/компонентных тестов API (Rest Assured).
* **Автоматическая очистка:** Плагин `maven-clean-plugin` настроен на автоматическую очистку директории `target` на фазе инициализации.

## Архитектура проекта и паттерны проектирования

Фреймворк разделен на независимые архитектурные слои согласно принципам **SOLID** (в частности, *Single Responsibility Principle*):

### 1. Слой управления сессией браузера (`by.kufar.driver`)
* **Паттерн Singleton (`Driver.java`)** — гарантирует существование строго одного инстанса WebDriver в рамках одного потока на протяжении теста. Это предотвращает утечки памяти и неконтролируемое открытие лишних окон браузера.
* **Слой управления ожиданиями (`WaitManager.java`)** — инкапсулирует логику работы с явными ожиданиями (`WebDriverWait`), избавляя тесты от «хардкодных» задержек (`Thread.sleep`).

### 2. Слой инфраструктуры страниц (`by.kufar.basepage`)
* **`BasePage.java`** — базовый класс для всех страниц. Накапливает в себе общие методы для работы с элементами (безопасные клики, ожидания видимости, ввод текста). Исключает дублирование базового кода Selenium в целевых классах страниц.

### 3. Бизнес-слой страниц (`by.kufar`)
* **Паттерн Page Object Model (POM)** — такие классы как `HomePage.java`, `SearchPage.java`, `AuthFormPage.java` и др., инкапсулируют внутри себя локаторы элементов веб-интерфейса.
* Они предоставляют тестам только верхнеуровневые бизнес-методы взаимодействия, скрывая под капотом низкоуровневую работу с Selenium WebDriver.

### 4. Тестовый слой (`by.kufar.api`)
* **`BaseTest.java`** — управляет жизненным циклом тестов (инициализация драйвера перед тестами `@Before...` и закрытие сессии браузера после тестов `@After...`).
* **Классы тестов** (`SearchTest`, `LoginTest` и др.) — содержат исключительно бизнес-логику проверок и вызовы шагов со страниц. Внутри тестовых классов полностью отсутствует прямое обращение к Selenium-драйверу или локаторам.



## Запуск проекта локально

### Требования к окружению
Перед запуском убедитесь, что у вас установлены:
* **JDK 19**
* **Apache Maven 3.8+**
* Браузер **Google Chrome** (или другой веб-драйвер, используемый в коде)

### Команды для сборки и запуска

1. **Клонируйте репозиторий:**
   ```bash
   git clone https://github.com
   ```

2. **Перейдите в папку проекта:**
   ```bash
   cd Tarasevich-kufar
   ```

3. **Запустите тесты (с автоматической очисткой и в 6 потоков):**
   ```bash
   mvn clean test
   ```

## Работа с отчетами Allure

В проекте используется связка Allure + AspectJ для сбора шагов, вложений и скриншотов. Результаты тестов автоматически складываются в папку `target/allure-results`.

### Генерация и просмотр отчета:

* **Вариант 1 (Локальный сервер):** Сгенерировать отчет во временную папку и сразу открыть его в браузере:
  ```bash
  mvn allure:serve
  ```

* **Вариант 2 (Сборка статического отчета):** Создать папку с готовым HTML-отчетом в `target/allure-report`:
  ```bash
  mvn allure:report
  ```
