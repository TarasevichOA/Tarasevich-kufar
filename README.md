# Kufar-TarasevichOA: Test Automation Framework

Репозиторий содержит современный фреймворк для автоматизации тестирования площадки объявлений Kufar. Проект сочетает в себе автоматизацию пользовательского интерфейса (**UI**) и проверку серверной части (**API**). Реализован параллельный запуск тестов для обеспечения высокой скорости сборки.

## Ключевые особенности фреймворка

* **Параллельное выполнение:** В `pom.xml` настроен встроенный параллельный запуск тестов средствами JUnit 5 (`fixed` стратегия конфигурации на **3 параллельных потока**).
* **Многослойные тесты:** Поддержка как классического UI-тестирования (Selenium), так и быстрых интеграционных/компонентных тестов API (Rest Assured).
* **Автоматическая очистка:** Плагин `maven-clean-plugin` настроен на автоматическую очистку директории `target` на фазе initialization.

## Архитектура проекта и паттерны проектирования

Фреймворк разделен на независимые архитектурные слои согласно принципам **SOLID** (в частности, *Single Responsibility Principle*):

### 1. Слой управления сессией браузера (`by.kufar.driver`)
* **Паттерн Singleton (`Driver.java`)** — гарантирует существование строго одного инстанса WebDriver в рамках одного потока на протяжении теста. В связке с `ThreadLocal` это обеспечивает потокобезопасность, предотвращает утечки памяти и неконтролируемое открытие лишних окон браузера.
* **Фабрика драйверов (`WebDriverFactory.java`)** — инкапсулирует логику создания инстансов браузеров Chrome, Firefox и Edge с автоматической конфигурацией аргументов (`window-size`, `headless`, `disable-blink-features`).
* **Слой управления ожиданиями (`WaitManager.java`)** — инкапсулирует логику работы с явными ожиданиями (`WebDriverWait`), избавляя тесты от «хардкодных» задержек (`Thread.sleep`).

### 2. Слой инфраструктуры страниц (`by.kufar.basepage`)
* **`BasePage.java`** — базовый класс для всех страниц. Накапливает в себе общие методы для работы с элементами (безопасные клики, ожидания видимости, ввод текста). Исключает дублирование базового кода Selenium в целевых классах страниц.

### 3. Бизнес-слой страниц (`by.kufar`)
* **Паттерн Page Object Model (POM)** — такие классы как `HomePage.java`, `SearchPage.java`, `AuthFormPage.java` и др., инкапсулируют внутри себя локаторы элементов веб-интерфейса. Они предоставляют тестам только верхнеуровневые бизнес-методы взаимодействия, скрывая под капотом низкоуровневую работу с Selenium WebDriver.

### 4. Тестовый слой (`by.kufar.api`)
* **`BaseTest.java`** — управляет жизненным циклом тестов через аннотации JUnit 5. В `@BeforeEach` динамически определяет имя теста, запускается изоляция логов и инициализируется страница. В `@AfterEach` браузер гарантированно закрывается, а контексты очищаются.
* **Классы тестов** (`SearchTest`, `LoginTest` и др.) — содержат исключительно бизнес-логику проверок и вызовы шагов со страниц. Внутри тестовых классов полностью отсутствует прямое обращение к Selenium-драйверу или локаторам. Кроссбраузерность реализована через `@ParameterizedTest` и `@ValueSource` для параллельного прогона сценариев в Chrome, Firefox и Edge с бизнес-описаниями в Allure через параметр `name`.

## Покрытие тестами

### 1. Многослойные тесты (UI & BDD)
Автоматизация пользовательского интерфейса полностью покрывает ключевые бизнес-сценарии взаимодействия с платформой:
* **Модуль аутентификации (`AuthFormTest`):** Тестирование формы авторизации, проверка валидности полей, обработка негативных сценариев с некорректными данными.
* **Модуль регистрации (`RegistrationTest`):** Проверка сквозного процесса создания новой учетной записи на платформе.
* **Восстановление пароля (`RecoverPasswordTest` & BDD):** Проверка логики сброса и восстановления доступа. Дополнительно реализован BDD-подход на базе фреймворка Cucumber — сценарии описаны на бизнес-языке в `.feature` файлах с шагами в `RecoverPasswordPageSteps`.
* **Домашняя страница (`HomeTest`):** Проверка базовых элементов интерфейса, работы виджетов, баннеров и навигационных панелей главного экрана.
* **Модуль поиска (`SearchTest`):** Реализованы комплексные сценарии сквозного поиска товаров на платформе, применение фильтров и валидация результатов выдачи.

### 2. Модуль API
* В пакете `by.kufar.api` (класс `LoginTest`) с помощью библиотеки Rest-Assured реализовано изолированное тестирование серверных запросов для авторизации. Генерация фейковых данных для запросов выполняется с помощью библиотеки `Datafaker`.

## Запуск проекта локально

### Требования к окружению
Перед запуском убедитесь, что у вас установлены:
* **JDK 19**
* **Apache Maven 3.8+**
* Браузеры **Google Chrome**, **Mozilla Firefox** или **Microsoft Edge**

### Команды для сборки и запуска

1. **Клонируйте репозиторий:**
   ```bash
   git clone https://github.com
   ```

2. **Перейдите в папку проекта:**
   ```bash
   cd Kufar-TarasevichOA
   ```

3. **Базовый запуск (Chrome в Headless-режиме):**
   ```bash
   mvn clean test
   ```

4. **Запуск в определенном браузере:**
   Благодаря конфигурации системных свойств в `WebDriverFactory`, вы можете явно передавать нужный браузер:
    * Запуск в **Firefox**: `mvn clean test -Dbrowser=firefox`
    * Запуск в **Edge**: `mvn clean test -Dbrowser=edge`

5. **Управление графическим режимом (Headless):**
   По умолчанию все тесты запускаются в скрытом режиме (`headless=true`). Если вам нужно запустить тесты с отображением браузера на экране, передайте флаг `false`:
   ```bash
   mvn clean test -Dheadless=false -Dbrowser=chrome
   ```

## 📊 Работа с отчетами Allure

В проекте используется связка Allure + AspectJ для автоматического сбора шагов, вложений и скриншотов. Результаты тестов складываются в папку `target/allure-results`.

### Генерация и просмотр отчета:

* **Вариант 1 (Локальный сервер):** Сгенерировать отчет во временную папку и автоматически открыть его в браузере:
  ```bash
  mvn allure:serve
  ```

* **Вариант 2 (Сборка статического отчета):** Создать папку с готовым HTML-отчетом в директории `target/allure-report`:
  ```bash
  mvn allure:report
  ```

## ⏱ Интеграция с CI/CD (Jenkins)

Фреймворк полностью автономен и интегрирован в CI/CD пайплайн Jenkins:
* **Сборка кода:** Настроена автоматическая джоба по скачиванию свежего кода из репозитория GitHub.
* **Расписание (Cron):** `10 19 * * 1,2,3,4,5` — автоматический старт тестов выполняется каждый будний день ровно в **19:10**.
* **Отчетность:** После завершения прогона Jenkins автоматически строит графики и тренды Allure.
